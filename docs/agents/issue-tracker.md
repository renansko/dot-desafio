# Issue tracker: GitHub

Repositório: `renansko/dot-desafio`. Usar `gh` para consultar e publicar issues.

- Consultar: `gh issue view <numero> --repo renansko/dot-desafio --comments`.
- Listar: `gh issue list --repo renansko/dot-desafio --state all`.
- Publicar com título em português, corpo Markdown via `--body-file` e label `needs-triage`.
- Seções: `What to build`, `Acceptance criteria`, `Blocked by`. Usar checkboxes nos critérios e links reais nos bloqueadores.
- Uma issue por questão do PDF. Publicar Q1 antes de Q2 e Q3.
- Ler a issue inteira e comentários antes de trabalhar. Não fechar ou modificar uma issue pai como efeito colateral.
- Publicar issues significa criar tickets no GitHub, não apenas arquivos locais.
